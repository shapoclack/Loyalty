# Loyalty
Программа лояльности для курса ПКС — приложение на Java 27, JavaFX 25 и PostgreSQL (JDBC). Основной интерфейс — графический; консольный режим сохранён для совместимости.

## Требования

- JDK 27 и Maven 3.9 или новее; `JAVA_HOME` должен указывать на JDK 27.
- Запущенный PostgreSQL и созданная база `loyalty`.
- Графическая сессия для запуска JavaFX и проверки окон.

JavaFX, драйвер PostgreSQL и Apache POI загружаются Maven автоматически.

## Запуск

```bash
createdb loyalty                 # один раз; таблицы и стартовые правила создаются при запуске
mvn clean javafx:run             # графический интерфейс
# или собрать JAR для текущей ОС и архитектуры:
mvn package
java --enable-native-access=ALL-UNNAMED -jar target/Loyalty-1.0-SNAPSHOT.jar
# консольный режим, если нужен:
java -jar target/Loyalty-1.0-SNAPSHOT.jar --console
```

Подключение настраивается в `src/main/resources/db.properties` или переменными окружения
`LOYALTY_DB_URL`, `LOYALTY_DB_USER`, `LOYALTY_DB_PASSWORD` (по умолчанию —
`jdbc:postgresql://localhost:5432/loyalty` под текущим пользователем ОС).
Переменные окружения имеют приоритет над файлом настроек. Пароль задавайте через
`LOYALTY_DB_PASSWORD`; локальные учётные данные не следует коммитить.
После изменения файла или переменных окружения перезапустите приложение.

Таблицы создаются автоматически, а демонстрационные данные добавляются в пустую базу.
Для запуска готового JAR используйте ту ОС и архитектуру, на которых он собран:
Maven включает соответствующие нативные библиотеки JavaFX.

## Графический интерфейс

Главное окно показывает клиентов из существующей базы PostgreSQL. Кнопки редактирования,
удаления, просмотра счетов и покупки доступны после выбора строки. Двойной щелчок открывает
карточку клиента. Регистрация автоматически открывает бонусный счёт и создаёт карту.
Редактирование позволяет изменить ФИО, телефон, email, дату рождения и статус. Удаление
требует подтверждения; клиент с историей операций защищён от удаления бизнес-правилом.

Поиск работает одновременно по ФИО, телефону и email без учёта регистра. Фильтры по статусу
клиента и уровню его карт можно комбинировать с поиском. У клиента может быть несколько
счетов: фильтр уровня проверяет наличие хотя бы одной карты такого уровня, а баланс
в основной таблице показывает сумму по всем его счетам, включая закрытые и заблокированные.
«Сбросить» очищает поиск и оба фильтра. После добавления клиента фильтры сбрасываются,
чтобы новая запись была видна. «Обновить» перечитывает данные из БД.

Нажатие заголовка столбца сортирует таблицу, повторное нажатие меняет направление.
Shift + нажатие добавляет второй параметр сортировки. ФИО, даты, суммы и остальные
столбцы поддерживают сортировку; числовые значения и даты сортируются по своему типу.
Список использует `ObservableList → FilteredList → SortedList`, компаратор `SortedList`
связан с `TableView.comparatorProperty()`. Поиск и фильтры применяются к загруженному
списку в памяти; серверная пагинация не реализована.

В карточке клиента доступны счета, блокировка и разблокировка карты, открытие нового
счёта, покупки клиента и история бонусов выбранной карты. В форме покупки карта
выбирается из `ComboBox` с номером, уровнем и балансом; вводить ID не требуется.
Можно рассчитать лимит списания и зарегистрировать покупку с начислением и списанием
по действующим правилам. Дата покупки назначается автоматически.

«Статистика» показывает 12 показателей по всей базе: количество клиентов, активных и
заблокированных, долю активных, количество счетов, общий, средний, минимальный и
максимальный баланс клиента, количество покупок, сумму покупок и средний чек.
Выбранный период (включая обе границы) влияет на три показателя покупок.
Статистика использует снимок загруженных данных; для обновления закройте её,
обновите главное окно и откройте снова.

«Экспорт CSV» выгружает **текущий отфильтрованный список в порядке таблицы**.
Путь выбирается через `FileChooser`; формат — UTF-8 с BOM, разделитель `;`, значения
экранируются. Excel-экспорт всей базы и управление правилами остаются доступны
в сохранённом консольном режиме.

Все запросы и экспорт выполняются в фоновом потоке, элементы окна на время операции
блокируются. Валидация выполняется до сохранения: обязательные поля, длины строк,
формат и уникальность телефона, формат email, дата рождения, диапазон и точность денежных
значений. Ошибки формы показываются в ней без закрытия, ошибки БД — через `Alert`.
Настройки подключения прежние; пароль не добавляется в исходники.

### FXML и разделение ответственности

- `src/main/resources/org/example/ui/`: `main.fxml`, `customer-form.fxml`,
  `customer-details.fxml`, `purchase.fxml`, `statistics.fxml`, `style.css`.
- FXML описывает компоновку; `fx:id` связывает элемент с полем `@FXML` контроллера,
  `onAction="#save"` — с обработчиком. Контроллер передаётся загрузчику через
  `FXMLLoader.setController`, чтобы внедрить сервисы через конструктор.
- `ui/controller/`: отдельные контроллеры списка, клиента, связанных данных,
  покупки и статистики. `ui/support/Ui` — загрузка FXML, фоновые задачи и диалоги.
- `service/`: бизнес-логика, валидация, фильтры, статистика и CSV-экспорт;
  `repository/`: SQL и связи; `model/`: существующие сущности предметной области.
- `Main` запускает `ui/LoyaltyApplication` по умолчанию. Ошибка подключения не закрывает
  окно: после восстановления доступности сервера можно повторить загрузку кнопкой «Обновить».

### Проверка

```bash
mvn test                           # валидация, поиск/фильтры, статистика, CSV
mvn -Dloyalty.integration=true test # дополнительно реальный PostgreSQL
mvn -Dloyalty.uiTest=true test      # дополнительно загрузка всех FXML и CSS (нужен рабочий стол)
mvn -Dloyalty.integration=true -Dloyalty.uiTest=true package # все проверки и сборка JAR
```

Интеграционный тест создаёт отдельную временную схему в настроенной БД и удаляет
её после проверки CRUD и покупки. Пользователю тестовой БД нужны права `CREATE SCHEMA`.
Данные основной схемы тест не изменяет. UI-тест открывает и закрывает тестовые окна,
проверяет загрузку FXML, применение CSS, ошибку пустой формы и некорректную дату.

## Возможности сервисов и консольного режима

- **Клиенты** — регистрация (сразу открывается бонусный счёт с картой), список с фильтром по статусу и сортировкой, поиск, карточка клиента, доп. счета, блокировка, удаление клиента без операций.
- **Бонусные счета** — все счета с фильтром по уровню/статусу и сортировкой, баланс, история транзакций, заявки на начисление/списание, блокировка.
- **Покупки и операции** — журнал операций (фильтр по периоду, магазину, сумме; сортировка), регистрация операции, списание бонусов в счёт оплаты, начисление на оплаченную деньгами часть, пересчёт уровня.
- **Списание бонусов** — заявка по операции → подтверждение / отмена; просроченная заявка получает статус `EXPIRED`.
- **Правила** — просмотр, добавление, включение/выключение и удаление (если правило не применялось) правил начисления и списания.
- **Экспорт в Excel** — вся база (лист на таблицу), история счёта по карте; результат фильтра журнала операций
  выгружается прямо из журнала. Файлы `.xlsx` сохраняются в каталог `exports/` (в `.gitignore`;
  переопределяется переменной `LOYALTY_EXPORT_DIR`).

Бизнес-правила:

- при начислении применяется самое выгодное из активных правил, подходящих по периоду действия и уровню счёта
  (`accrual_rule.category` = `BASE` / `SILVER` / `GOLD`, пусто — для всех);
- списание ограничено `max_percent` суммы операции, `min_amount`/`max_amount` и балансом; действует самое новое активное правило;
- уровень: `SILVER` от 10 000, `GOLD` от 50 000 суммарных покупок.

## Тестовые данные

`seed.sql` заполняет пустую базу: 6 клиентов (ACTIVE / BLOCKED), 7 счетов (уровни BASE / SILVER / GOLD,
статусы ACTIVE / BLOCKED / CLOSED), 15 покупок в трёх магазинах за январь–сентябрь 2026,
15 заявок на начисление, 5 заявок на списание (APPROVED, PENDING, CANCELLED, EXPIRED), 16 транзакций.
Балансы счетов согласованы с транзакциями. Карты: `7700000000000001` … `7700000000000007`.

## Как расширять

| Что нужно | Что сделать |
|---|---|
| Новый тип правила начисления | реализовать `AccrualCalculator`, зарегистрировать в `AccrualCalculatorRegistry.defaults()` |
| Другая логика уровней | реализовать `TierPolicy`, передать в `AppContext` |
| Новое окно JavaFX | добавить FXML в `resources/org/example/ui`, контроллер в `ui/controller` и переход из интерфейса |
| Новый раздел консольного меню | реализовать `MenuSection`, добавить в список разделов `AppContext` |
| Новый тип операции (возврат и т.п.) | добавить значение в `OperationType` и сервис-сценарий по образцу `PurchaseService` |
| Отложенное начисление | `AccrualService.process` уже отделён от создания заявки (`PENDING` → `APPROVED`/`REJECTED`) |
| Новая выгрузка в Excel | собрать листы через `ExportSheet.of(...)` в `ExportService` и вызвать `ExcelExporter` |
| Изменение схемы | `schema.sql` (идемпотентный, выполняется при каждом запуске) |
