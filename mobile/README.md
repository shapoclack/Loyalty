# Подключение мобильного приложения

`api-client.ts` — независимый от UI TypeScript-клиент для будущего мобильного приложения, например React Native. Мобильный UI в задачу не входит.

1. Создайте `LoyaltyApi(baseUrl, secureTokenStore)`. `baseUrl` — origin сервера без `/api`.
2. Реализуйте `TokenStore` через Keychain/Android Keystore (например, адаптер SecureStore). Access JWT остаётся только в памяти.
3. Вызовите `login(login, password)`. Клиент отправляет `mobile: true`: сервер возвращает refresh-токен в JSON, без cookie.
4. Если `user.mustChangePassword`, покажите обязательную смену пароля и затем повторный вход.
5. При холодном старте вызывайте `refresh()`. Refresh ротируется; клиент сериализует одновременные запросы обновления и сохраняет новый токен.
6. Для изменений отправляйте текущий `version`. При 409 обновите карточку и предложите пользователю повторить изменения.
7. `logout()` отзывает серверную сессию, затем очищает secure storage. Не удаляйте токен до успешного сетевого ответа, если важен гарантированный отзыв.

Роли и права проверяет сервер, UI лишь скрывает недоступные действия. Типы всех остальных операций доступны в `/v3/api-docs`; контракт описан в `backend/README.md`.

Compose намеренно публикует порты только на localhost. Для Android Emulator используйте адрес хоста `10.0.2.2:8080`, для iOS Simulator — `localhost:8080`. Физическому устройству нужен отдельно настроенный HTTPS endpoint; не открывайте PostgreSQL наружу. CORS для нативного клиента не нужен.
